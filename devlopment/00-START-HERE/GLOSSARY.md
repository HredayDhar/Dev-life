# Glossary of Software Engineering Terms

This glossary defines key terms used throughout the 48-phase Software Engineering Development Process & Developer Training Playbook. Understanding these terms is essential for following the material and applying the concepts effectively.

## A

**Agile Methodology**: An iterative approach to software development that emphasizes flexibility, customer collaboration, and rapid delivery of working software through short cycles called sprints.

**API (Application Programming Interface)**: A set of rules and protocols that allows different software applications to communicate with each other, defining how components should interact.

**Architecture**: The fundamental structure of a software system, including its components, their relationships, and the principles governing its design and evolution.

**Asynchronous Processing**: A programming model where operations can proceed without waiting for each other to complete, enabling better resource utilization and responsiveness.

## B

**Backend**: The server-side portion of a software application that handles data processing, storage, and business logic, typically not visible to end users.

**Beta Testing**: A phase of software testing where a nearly complete version is released to a limited external audience to identify issues before general availability.

**Branching (in Git)**: Creating a separate line of development in version control to work on features, fixes, or experiments without affecting the main codebase.

**Build Process**: The automated steps that transform source code into a runnable software product, including compilation, packaging, and dependency resolution.

## C

**CI/CD (Continuous Integration/Continuous Deployment)**: Practices that automate the integration of code changes (CI) and their release to production (CD), enabling frequent, reliable software delivery.

**Cache**: A high-speed data storage layer that stores a subset of data to reduce access time compared to fetching from the primary storage location.

**Code Review**: The systematic examination of source code by one or more developers to identify defects, ensure adherence to standards, and share knowledge.

**Cohesion**: The degree to which elements within a module belong together; high cohesion means elements are strongly related and focused on a single purpose.

**Concurrency**: The ability of a system to handle multiple operations overlapping in time, making progress on several tasks seemingly simultaneously.

**Configuration Management**: The process of systematically handling changes to a system to maintain its integrity over time, including tracking versions and dependencies.

**Containerization**: A lightweight form of virtualization that packages an application and its dependencies into a portable container that runs consistently across environments.

**Continuous Testing**: The practice of executing automated tests as part of the software delivery pipeline to obtain immediate feedback on business risks.

## D

**Database**: An organized collection of structured information stored electronically, typically managed by a Database Management System (DBMS).

**Debugging**: The process of identifying, analyzing, and removing errors or bugs from software code.

**Deployment**: The process of making a software system available for use, typically involving installation, configuration, and activation in a target environment.

**Design Pattern**: A general, reusable solution to a commonly occurring problem in software design, representing best practices that developers can apply to similar situations.

**DevOps**: A set of practices that combines software development (Dev) and IT operations (Ops) to shorten the development lifecycle and provide continuous delivery with high quality.

## E

**End-to-End Testing**: A methodology that tests the complete flow of an application from start to finish to ensure all integrated components work together as expected.

**Environment**: A specific deployment context (e.g., development, staging, production) with its own configuration, infrastructure, and data.

**Error Handling**: The process of responding to and recovering from error conditions in software in a way that maintains system stability and provides meaningful feedback.

**Event-Driven Architecture**: A software architecture paradigm where components communicate through events, promoting loose coupling and scalability.

**Exploratory Testing**: An approach to testing where testers actively explore the software without predefined test cases, learning and designing tests simultaneously.

## F

**Failover**: The automatic switching to a redundant or standby system upon the failure of the currently active system to maintain availability.

**Feature Flag**: A technique that allows developers to enable or disable functionality remotely without deploying new code, facilitating controlled rollouts and experimentation.

**Frontend**: The client-side portion of a software application that users interact with directly, typically including the user interface and user experience elements.

**Functional Testing**: A type of testing that verifies that each function of the software application operates in conformance with the requirement specification.

**Fuzz Testing**: A software testing technique that involves providing invalid, unexpected, or random data as inputs to a program to uncover coding errors and security vulnerabilities.

## G

**Garbage Collection**: An automatic memory management feature that reclaims memory occupied by objects that are no longer in use by the program.

**Git**: A distributed version control system for tracking changes in source code during software development, enabling collaboration among developers.

**Golden Path**: The most common or important user journey through an application, typically representing the primary value delivery scenario.

**Governance**: The framework of policies, procedures, and standards that guide decision-making and ensure accountability in software development and IT operations.

**Growth Mindset**: The belief that abilities and intelligence can be developed through dedication and hard work, essential for continuous learning in software engineering.

## H

**High Availability**: A system design approach and associated service implementation that ensures a prearranged level of operational performance will be met during a contractual measurement period.

**Horizontal Scaling**: Adding more machines or nodes to a system to handle increased load, as opposed to vertical scaling (adding power to existing machines).

**Hotfix**: An urgent software fix deployed to production to address a critical issue, typically bypassing the normal release cycle.

**HTML (HyperText Markup Language)**: The standard markup language for documents designed to be displayed in web browsers and assisted by technologies like CSS and JavaScript.

**HTTP (Hypertext Transfer Protocol)**: The foundation of data communication for the World Wide Web, defining how messages are formatted and transmitted.

## I

**Idempotency**: A property of operations where applying them multiple times has the same effect as applying them once, important for distributed systems and error recovery.

**Incremental Development**: A software development approach where the system is built and delivered in pieces (increments), each adding functional capability.

**Integration Testing**: A level of software testing where individual units are combined and tested as a group to verify they work together correctly.

**Interface**: A shared boundary across which two separate components of a computer system exchange information, defining how they interact without specifying internal implementation.

**Issue Tracking**: The process of reporting, monitoring, and managing software defects, enhancements, and tasks throughout the development lifecycle.

**Iterative Development**: A software development approach that repeats cycles (iterations) of planning, development, testing, and review to gradually refine and expand the system.

## J

**JavaScript Object Notation (JSON)**: A lightweight data interchange format that is easy for humans to read and write and easy for machines to parse and generate.

**JUnit**: A simple framework for writing repeatable tests in the Java programming language, commonly used for unit testing.

## K

**Kanban**: A visual workflow management method that helps teams visualize work, limit work-in-progress, and maximize efficiency or flow.

**Kernel**: The core component of an operating system that manages system resources and communication between hardware and software.

**Key Performance Indicator (KPI)**: A measurable value that demonstrates how effectively a company is achieving key business objectives, often used to monitor system performance.

## L

**Latency**: The time delay between the cause and the effect of a physical change in the system being observed, particularly important in networked and distributed systems.

**Legacy System**: An existing software system or application that continues to be used because it fulfills a business need, often despite being outdated or difficult to maintain.

**Load Testing**: A type of performance testing that determines how a system behaves under both normal and anticipated peak load conditions.

**Local Development Environment**: A developer's personal setup for writing, testing, and debugging code before sharing it with others or deploying to shared environments.

**Logging**: The practice of recording events and data about software execution to aid in debugging, monitoring, and auditing.

## M

**Maintainability**: The ease with which a software system can be modified to correct faults, improve performance, or adapt to a changed environment.

**Microservices**: An architectural style that structures an application as a collection of loosely coupled services, each implementing a specific business capability.

**Middleware**: Software that provides common services and capabilities to applications beyond what's offered by the operating system, acting as a "software glue."

**Migration**: The process of moving data, applications, or other business elements from one environment to another, often involving transformation and validation.

**Mock Object**: A simulated object that mimics the behavior of real objects in controlled ways, typically used in unit testing to isolate the unit under test.

**Monitoring**: The continuous observation of a system's operations to detect issues, track performance, and ensure it's functioning as expected.

**Monolith**: A software architecture where all components are tightly integrated and deployed as a single unit, as opposed to modular or distributed approaches.

**Mutation Testing**: A method of software testing that involves modifying a program's source code in small ways to check if the existing test cases can detect the changes.

## N

**Native Application**: A software program developed for use on a particular platform or device, written in languages specific to that platform (e.g., Swift for iOS, Kotlin for Android).

**Network Latency**: The time it takes for a data packet to travel from one designated point to another in a network, typically measured in milliseconds.

**Node.js**: An open-source, cross-platform JavaScript runtime environment that executes JavaScript code outside a web browser, enabling server-side scripting.

**Non-Functional Requirements**: Requirements that specify criteria that can be used to judge the operation of a system, rather than specific behaviors (e.g., performance, security, usability).

**Normalization**: The process of organizing data in a database to reduce redundancy and improve data integrity by dividing large tables into smaller, related tables.

## O

**Object-Oriented Programming (OOP)**: A programming paradigm based on the concept of "objects" that can contain data and code to manipulate that data.

**Observability**: The ability to understand the internal state of a system from its external outputs, particularly through logs, metrics, and tracing.

**Open Source Software**: Software with source code that anyone can inspect, modify, and enhance, typically developed collaboratively and distributed under licenses that permit sharing.

**Operating System (OS)**: System software that manages computer hardware, software resources, and provides common services for computer programs.

**Orchestration**: The automated arrangement, coordination, and management of complex computer systems, middleware, and services.

**Outage**: A period during which a service or system is unavailable or not performing its primary function as expected.

## P

**Pair Programming**: An agile software development technique where two programmers work together at one workstation, with one writing code while the other reviews each line.

**Performance Testing**: Testing performed to determine how a system performs in terms of responsiveness and stability under a particular workload.

**Persistence**: The characteristic of data that outlives the execution of the program that created it, typically stored in databases or file systems.

**Pipeline**: A set of automated processes that enable developers and DevOps professionals to reliably and efficiently compile, build, test, and deploy their code.

**Polyglot Persistence**: The use of different data storage technologies to handle varying data storage needs within the same application.

**Postmortem**: A documented analysis of an incident or failure that describes what happened, why it happened, the impact, and actions to prevent recurrence.

**Preproduction Environment**: A staging environment that closely mimics production, used for final testing and validation before releasing to users.

**Pull Request**: A method of submitting contributions to a development project, commonly used with Git-based version control systems, where changes are reviewed before merging.

## Q

**Quality Assurance (QA)**: Systematic activities implemented in a quality system to ensure that products or services fulfill specified requirements for quality.

**Quality Gate**: A predefined checkpoint in the software development lifecycle where specific criteria must be met before proceeding to the next phase.

**Query**: A request for data or information from a database, typically expressed in a formal query language like SQL.

**Queue**: A data structure that follows the First-In-First-Out (FIFO) principle, used for managing tasks or data packets in order of arrival.

## R

**Race Condition**: A situation where the behavior of software depends on the sequence or timing of uncontrollable events, often leading to bugs that are difficult to reproduce.

**Refactoring**: The process of restructuring existing computer code without changing its external behavior to improve non-functional attributes like readability and maintainability.

**Regression Testing**: A type of software testing that ensures that recent code changes have not adversely affected existing functionality.

**Release Management**: The process of managing, planning, scheduling, and controlling a software build through different stages and environments, including testing and deploying releases.

**Repository**: A central location where data is stored and managed, particularly in version control systems where code and its history are kept.

**Requirements**: Documentation describing what a software system should do, including functional and non-functional aspects, serving as the foundation for design and implementation.

**Rollback**: The process of reverting a system to a previous known-good state, typically used when a deployment introduces unacceptable issues.

**Root Cause Analysis**: A method of problem-solving used to identify the underlying reasons for faults or problems, rather than just addressing symptoms.

**Routing**: The process of selecting paths in a network along which to send network traffic, determining how data packets reach their destinations.

## S

**SaaS (Software as a Service)**: A software distribution model where applications are hosted by a provider and made available to customers over the internet, typically on a subscription basis.

**Scalability**: The capability of a system to handle a growing amount of work by adding resources to the system, either by scaling up (vertical) or out (horizontal).

**Scrum**: An agile framework for developing, delivering, and sustaining complex products, emphasizing teamwork, accountability, and iterative progress.

**Security Testing**: A process intended to reveal flaws in the security mechanisms of an information system that protect data and maintain functionality as intended.

**Separation of Concerns**: A design principle for separating a computer program into distinct sections, each addressing a separate concern to improve maintainability and clarity.

**Service Level Agreement (SLA)**: A commitment between a service provider and a client that outlines the level of service expected, including metrics like uptime and response time.

**Session**: A semi-interactive exchange of information between two or more devices, or between a user and a computer system, typically with a defined start and end.

**Shadow Testing**: A technique where new code runs in parallel with existing code, processing the same inputs but not affecting outputs, to validate behavior before full deployment.

**Sharding**: A database partitioning technique that separates very large databases into smaller, faster, more easily managed parts called shards.

**Smoke Testing**: Preliminary testing to reveal simple failures severe enough to reject a prospective software release, also known as "build verification testing."

**Software Development Lifecycle (SDLC)**: The process of planning, creating, testing, and deploying an information system, encompassing all stages from conception to retirement.

**Source Code**: The human-readable instructions written by programmers in a programming language that specify how software should behave.

**Spectre and Meltdown**: Hardware vulnerabilities affecting modern processors that allow programs to steal data currently being processed on the computer.

**SQL (Structured Query Language)**: A domain-specific language used for managing and manipulating relational databases.

**Stack Trace**: A report of the active stack frames at a certain point in time during the execution of a program, useful for debugging.

**State Management**: The process of handling the state of an application—data that represents the current status or condition of the system at a given point in time.

**Static Analysis**: The examination of source code without executing it, used to find potential vulnerabilities, bugs, and code smells.

**Stress Testing**: A form of testing that evaluates system behavior under extreme conditions, beyond normal operational capacity, often to a breaking point.

**Sprint**: A time-boxed period in Scrum during which specific work has to be completed and made ready for review, typically lasting 2-4 weeks.

**Standup Meeting**: A short, daily team meeting where members share progress, plans, and obstacles, typically lasting 15 minutes or less.

**Static Typing**: A typing system where type checking is performed during compile-time rather than at runtime, helping catch errors early.

**Storage Area Network (SAN)**: A dedicated high-speed network that provides access to consolidated, block-level storage, typically used in enterprise environments.

**Supply Chain Security**: The practice of securing the end-to-end process of software creation, from source code dependencies to distribution, to prevent tampering.

**Switch Statement**: A control mechanism that allows the value of a variable or expression to change the control flow of program execution via a multi-way branch.

**Synchronous Processing**: A programming model where operations occur in sequence, with each operation needing to complete before the next can begin.

**System Integration**: The process of bringing together component subsystems into one comprehensive system and ensuring they function together as intended.

## T

**Technical Debt**: The implied cost of additional rework caused by choosing an easy solution now instead of using a better approach that would take longer.

**Test Coverage**: A measure used to describe the degree to which the source code of a program is executed when a particular test suite runs.

**Test-Driven Development (TDD)**: A software development process that relies on the repetition of a very short development cycle: requirements are turned into specific test cases, then code is written to pass the tests.

**Throughput**: The amount of work or number of transactions processed by a system in a given amount of time, often measured in requests per second.

**Throttling**: The intentional slowing down or speeding up of a process, typically used to control resource usage or prevent system overload.

**Time-to-Market**: The length of time it takes from a product being conceived until its being available for sale, a critical metric in competitive industries.

**Toggle**: A user interface element that allows users to switch between two states, such as on/off or show/hide.

**Topology**: The arrangement of the various elements (links, nodes, etc.) of a computer network, defining how they are interconnected.

**Traceability**: The ability to trace and verify the history, location, or application of an item by means of documented recorded identification.

**Trade-off**: A balance achieved between two desirable but incompatible features; a compromise where gaining one aspect means losing another.

**Transaction**: A logical unit of work that contains one or more database operations, typically following ACID properties (Atomicity, Consistency, Isolation, Durability).

**Tree Shaking**: A term commonly used in JavaScript context for dead-code elimination, removing unused modules from the bundle during the build process.

**Troubleshooting**: A systematic approach to problem-solving that is often used to find and correct issues with complex machines, electronics, computers, and software systems.

**Type Safety**: The extent to which a programming language discourages or prevents type errors, helping ensure program correctness.

**Typedef**: A keyword used in C and C++ to give an existing data type another name, improving code readability.

## U

**Ubuntu**: A popular Linux distribution based on Debian, known for its user-friendliness and strong community support.

**UDID (Unique Device Identifier)**: A unique string of characters that identifies a specific Apple device, used by developers for testing and distribution.

**UI (User Interface)**: The means by which a user interacts with a computer system, particularly the use of input devices and software.

**UML (Unified Modeling Language)**: A standardized modeling language consisting of an integrated set of diagrams developed to help system and software developers specify, visualize, construct, and document software systems.

**Unit Testing**: A software testing method where individual units or components of a software are tested in isolation to validate that each unit performs as designed.

**Unix**: A family of multitasking, multiuser computer operating systems that derive from the original AT&T Unix, with Linux being a prominent open-source clone.

**Upgrade**: The process of replacing a product with a newer version of the same product, often involving data migration and compatibility testing.

**URL (Uniform Resource Locator)**: A reference to a web resource that specifies its location on a computer network and a mechanism for retrieving it.

**Usability Testing**: A technique used to evaluate a product by testing it on representative users, observing how they interact with it to identify usability problems.

**User Acceptance Testing (UAT)**: The final phase of testing where actual users test the software to ensure it can handle required tasks in real-world scenarios, according to specifications.

**User Story**: An informal, natural language description of features of a software system written from the perspective of an end user, typically following the format: "As a [type of user], I want [some goal] so that [some reason]."

**User Experience (UX)**: The overall experience of a person using a product such as a website or computer application, particularly in terms of how easy or pleasing it is to use.

**User**: A person who utilizes a computer or network service, the ultimate consumer of software functionality.

## V

**Validation**: The process of checking that a software system meets specifications and fulfills its intended purpose, often involving user acceptance testing.

**Version Control**: A system that records changes to a file or set of files over time so that specific versions can be retrieved later, essential for collaborative software development.

**Virtual Machine (VM)**: An emulation of a computer system that provides the functionality of a physical computer, enabling multiple operating systems to run on a single physical machine.

**Virtualization**: The creation of a virtual (rather than actual) version of something, such as a hardware platform, operating system, storage device, or network resource.

**Virus**: A type of malicious software program that, when executed, replicates by reproducing itself or infecting other programs by modifying them.

**Visibility**: The extent to which internal system states and operations can be observed from the outside, critical for debugging, monitoring, and observability.

**VLAN (Virtual Local Area Network)**: A logical subgroup within a local area network that is created via software rather than by physically moving cables or wires.

**VMware**: A company providing cloud computing and virtualization software and services, pioneering the x86 architecture virtualization.

**VoIP (Voice over Internet Protocol)**: A methodology and group of technologies for the delivery of voice communications and multimedia sessions over Internet Protocol networks.

**Vulnerability**: A weakness in a system that can be exploited by a threat actor to perform unauthorized actions within a computer system.

## W

**Waterfall Model**: A linear sequential flow in software development where progress is seen as flowing steadily downwards through phases like requirements, design, implementation, testing, and maintenance.

**Webhook**: A way for an application to provide other applications with real-time information, delivering data to other applications as it happens.

**White Box Testing**: A method of software testing that tests internal structures or workings of an application, as opposed to its functionality.

**Whitebox Cryptography**: A technique aimed at protecting cryptographic implementations from extraction in contexts where the execution environment is not trusted.

**Wi-Fi**: A family of wireless network protocols based on the IEEE 802.11 standards that are commonly used for local area networking and internet access.

**Windows**: A group of proprietary graphical operating systems developed and marketed by Microsoft, widely used in personal computing and enterprise environments.

**Wireframe**: A visual guide that represents the skeletal framework of a website or application, used to plan the layout and functionality.

**Work-in-Progress (WIP) Limit**: A constraint on how many work items can be in a particular state at any given time, a key concept in Kanban and lean methodologies.

**Workaround**: A temporary solution to bypass a known problem in a system, typically used while a permanent fix is being developed.

**Working Directory**: The directory in which a process is currently executing, often relevant in command-line interfaces and build scripts.

**Wrapper**: A library or module that encapsulates another library or module to provide a different interface, often to simplify usage or add functionality.

**Write-Ahead Logging (WAL)**: A family of techniques for providing atomicity and durability in database systems, where changes are logged before being applied to the main data.

## X

**XML (eXtensible Markup Language)**: A markup language that defines a set of rules for encoding documents in a format that is both human-readable and machine-readable.

**XPath**: A query language for selecting nodes from an XML document, enabling navigation through elements and attributes in an XML tree.

**XSS (Cross-Site Scripting)**: A type of security vulnerability typically found in web applications that enables attackers to inject client-side scripts into web pages viewed by other users.

## Y

**YAML (YAML Ain't Markup Language)**: A human-readable data serialization language that is commonly used for configuration files and data exchange.

**Yield**: In programming, particularly with generators, the value produced by a generator function each time it is resumed.

## Z

**Zero Downtime Deployment**: A deployment strategy that allows updating a system without causing service interruption, essential for high-availability applications.

**Zero Trust**: A security concept centered on the belief that organizations should not automatically trust anything inside or outside their perimeters and must verify anything and everything trying to connect to their systems.

**Zombie Process**: A process that has completed execution but still has an entry in the process table, waiting for its parent process to read its exit status.

**Zoom**: A video communications app that provides video telephony and online chat services through a cloud-based peer-to-peer software platform.
